# Company Change Monitoring Runbook

## Purpose

Company Change Monitor watches the 11 ModularHub company profiles for new public signals and produces review candidates. It does not update public company data, business data, news data, or production deployments by itself.

The pipeline separates three concepts:

- Signal: a source observation such as a public news item, disclosure, procurement notice, or patent record.
- Candidate: a structured change proposal generated by comparing a signal with current verified company data.
- Verified fact: a human-approved data update with sufficient source evidence.

Signals and candidates are not verified facts.

## Public Data Safety

- `publish` defaults to false and `publish=true` fails.
- Candidate review queues are written to internal data/artifact paths, never to `frontend/public`.
- Patch proposal metadata requires both `create_proposal=true` and `acknowledge_proposal=true`.
- Low and medium confidence candidates remain review-only.
- News-only signals are not promoted to company profile patches.
- Automatic merge is not supported.

## Sources

Daily sources:

- DART/OpenDART for filings and identity-sensitive records.
- NAVER API HUB for market signals.
- Existing public news JSON for offline review and regression-safe signal generation.

Weekly sources:

- Official company websites.
- Public procurement and awarding agencies.
- Patent sources.

Monthly work:

- Full 11-company data quality audit.
- Financial, facility, project, and patent evidence review.

GitHub cron values use UTC. The workflow runs at `20:45 UTC`, which is `05:45 KST`.

## Identity Policy

Company identity policy lives in:

```powershell
config\company_change_monitoring\company_identities.json
```

Matching must use more than a company name when proposing material changes. Strong evidence includes corp code, official domain, representative, region, existing project evidence, or patent applicant/owner evidence.

Daeseung Engineering includes explicit exclusions for:

- 김해 수처리·제진기 업체
- 자동차 부품 대승
- 대승그룹
- 대표자 최병천

## Confidence

Allowed values:

- `high`
- `medium`
- `low`
- `unknown`

Tier 2 news alone is capped at medium. Tier 3 sources cannot directly support important identity, financial, facility, or patent changes.

## Risk

Allowed values:

- `low`
- `moderate`
- `high`
- `critical`

High-risk fields include representative, legal name, headquarters, production status, production capacity, financials, contract amount, project completion, and patent owner/status.

## Candidate Status

Allowed values:

- `pending`
- `duplicate`
- `conflict`
- `insufficient_evidence`
- `rejected`
- `accepted`
- `proposed`
- `published`

Collectors only create `pending`, `duplicate`, `conflict`, or `insufficient_evidence` candidates. Human review is required before accepted/proposed/published states.

## Local Dry Run

```powershell
python scripts\company_change_monitoring\build_change_review_queue.py --companies gs-ec,yuchang-enc,daeseung-engineering --sources public_news --lookback-days 30
python scripts\audit_company_change_candidates.py
```

All 11 companies:

```powershell
python scripts\company_change_monitoring\build_change_review_queue.py --sources public_news --lookback-days 30
python scripts\audit_company_change_candidates.py
```

Proposal guard example:

```powershell
python scripts\company_change_monitoring\build_change_review_queue.py --create-proposal
```

The command above must fail. Proposal metadata requires:

```powershell
python scripts\company_change_monitoring\build_change_review_queue.py --create-proposal --acknowledge-proposal
```

## GitHub Issues

High or critical candidates can be turned into review issues with labels:

- `company-intelligence`
- `data-review`
- `change-detected`

Issue dedupe must use the candidate fingerprint. Issue bodies must not include secrets, raw payloads, request headers, or local file paths.

## Review Procedure

1. Read the digest.
2. Inspect high-priority and conflict candidates first.
3. Confirm identity evidence.
4. Verify source tier and source URL.
5. Check whether a research gap is resolved, partially resolved, conflicting, or still open.
6. If the candidate is accepted, create a separate human-reviewed data update PR.
7. Run company data quality audit and frontend regression tests before merging any public data update.

## Rollback

Because the monitor does not publish public data, rollback normally means discarding artifacts or closing generated review issues. If a later human-approved data PR introduces a bad update, revert that data PR and rerun the company data quality audit.
